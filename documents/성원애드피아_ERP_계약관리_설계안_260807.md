# 성원애드피아 ERP 계약 관리 설계안

> **작성일:** 2026-08-07
> **대상 문서:** 통합정책서 v1.9 (정책 반영은 화면 설계 확정 후 v2.0 으로 일괄 — §7)
> **대상 화면:** 인사 > 계약 관리 (`assets/js/page-hr-contract.js`)

---

## 1. 개요

계약서 작성은 **계약 관리 화면에서만** 진행한다. 최초 입사 시 자동 생성분과, 계약 관리에서 작성하는 갱신분 두 갈래다.

```
STEP 1  계약서 종류  →  STEP 2  대상자  →  STEP 3  값 입력  →  STEP 4  발송
        근로 | 임금        조회 + 선택       편집 그리드        결재 없음
```

인사기록카드에서의 개별 작성은 **삭제한다** (계약 이력 조회는 유지).

---

## 2. 계약 작성 루트

| 루트 | 진입 | 흐름 |
|---|---|---|
| **Route 1 · 입사** | 임직원 등록 | 근로·임금계약서 자동 생성 → 근로자 서명 → **입사 승인 = 계약 체결** / 입사 반려 = 폐기 |
| **Route 2 · 계약 관리** | 계약서 작성 (개별·일괄) | 발송 → 근로자 서명 → **권한자 서명 = 계약 완료** |

Route 1 의 최초 계약은 회수할 수 없다 (`:517` `canCancel=false`, 현행 유지).

---

## 3. 계약 관리 화면 구조

```
[계약 내역]  [계약서 이력]
```

| 탭 | 단위 | 용도 |
|---|---|---|
| **계약 내역** | 발송 1건 | 발송건 진행 추적 · 회수 · 재발송 |
| **계약서 이력** | 계약서 1건 | 계약서 조회 · PDF 다운로드 |

Route 1·2 로 발송된 건이 모두 **발송 단위**로 계약 내역에 쌓인다. 계약 건수 폭증(일용직 월 계약 시 연 수백 건)을 발송 단위로 접어서 해결한다.

### 계약 내역 그리드

| 컬럼 | 정렬 | 값 |
|---|---|---|
| No | 중앙 | 내림차순 |
| 계약서 종류 | 중앙 | `입사 근로계약서` · `입사 임금계약서` · `근로계약서` · `임금계약서` |
| 상태 | 중앙 | §5.2 · 진행 건수 병기 (`계약 진행 중 20/27`) |
| 발송자 | 좌측 | |
| 발송일시 | 중앙 | `YY/MM/DD   HH:MM` |

Route 1 발송분은 `입사` 접두어로 구분한다.

## 4. 계약서 작성 플로우

### 4.1 STEP 1 — 계약서 종류

**근로계약서 / 임금계약서 중 하나**를 선택한다 (라디오).

| 종류 | 대상 | 임금 유형 |
|---|---|---|
| 근로계약서 | 정규직 · 계약직 · 일용직 · 프리랜서 | — |
| 임금계약서 | 정규직 · 계약직 / 일용직 / 프리랜서 | 연봉제 / 시급제 / 계약기간·총 계약금액 |

- **도급직은 계약 대상이 아니다** — 목록에 노출하지 않는다
- 종류를 먼저 고르는 이유 — 대상자 모집단이 결정되어 부적격자를 고를 수 없고, STEP 3 그리드 컬럼이 종류마다 다르다
- **세트 개념을 두지 않는다.** 근로·임금을 모두 새로 써야 하는 경우 **근로 한 번 · 임금 한 번, 두 번의 작성·발송**으로 진행한다. 수습 → 정규직 전환과 일용직 월 갱신이 여기 해당하며, 한 사람을 전환시키는 데 발송이 2건 발생한다 *(2026-08-07 확정)*

### 4.2 STEP 2 — 대상자

**로직을 코드에 박지 않는다.** 조회 조건을 조합해 좁히고, 자주 쓰는 조합은 저장해 재사용한다.

```
계약 날짜   ( ) 계약 종료일   (•) 계약 시작일        ← 라디오
            ( ) 월별          (•) 일별               ← 라디오
            [ 2027-02-28 ]

입사일      [ 2026-02-28 ]   (•) 이전  ( ) 이후      ← 라디오

사원유형    (•) 정규직  ( ) 계약직  ( ) 일용직  ( ) 프리랜서    ← 라디오 (단일)
재직상태    [x] 재직   [ ] 휴직                                ← 체크박스 (복수)
            [x] 수습해제 승인 완료                             ← 체크박스
```

| 조건 | 비고 |
|---|---|
| 계약 날짜 | 기준(종료일/시작일)과 단위(월별/일별)를 라디오로 고른다. 추출 조건이 **정확히 일치**이지 범위가 아니라 from~to 를 쓰지 않는다 |
| 입사일 | 단일 날짜 + **이전/이후** 선택. 계약서 종류에 따라 기본값이 다르다 (아래) |
| 재직상태 | 퇴직자는 목록에 없다. 휴직자 포함 여부는 §8 백로그 |
| 수습해제 | 승인 완료자만 조회 |

#### 입사일 기본값이 종류마다 다른 이유

| 종류 | 기본값 | 왜 |
|---|---|---|
| **임금** | `[D − 12개월] 이전` | 연봉 인상은 근속 1년 이상 대상 → 오래된 입사자 |
| **근로** | `이후` (날짜 비움) | 수습 → 정규직 전환은 최근 입사자 → 최근 입사자 |

`D = 오늘 이후 가장 가까운 인상 기준일(2월 28일)`. 계약 종료일을 입력하면 임금계약일 때 입사일 칸이 `종료일 − 12개월` 로 자동 채워진다. 담당자가 수정할 수 있다.

#### 업무별 조회 조건

| 업무 | 종류 | 조건 |
|---|---|---|
| 정규직 연봉 인상 | 임금 | 계약 종료일 = D · 입사일 ≤ D−12개월 |
| 수습 → 정규직 전환 (근로) | 근로 | 수습해제 승인 완료 |
| 수습 → 정규직 전환 (임금) | 임금 | 수습해제 승인 완료 |
| 일용직 월 계약 | 임금 | 계약 종료일 = 전월 말일 |
| 기간제 만료 갱신 | 근로 | 계약 종료일 = 해당 월 |
| 무기 임금계약 확인 | 임금 | 계약 **시작일** ≤ D−12개월 |

> **무기 임금계약은 시작일 기준으로 조회한다.** 종료일이 없어 종료일 기준 추출에 안 잡히므로, 기준을 시작일로 바꿔 "마지막 인상 후 1년 경과" 로 찾는다.

#### 공통 규칙

- **진행 중인 계약이 있는 사람은 제외한다.** `서명 대기` · `서명 완료` 상태의 계약을 가진 직원은 중복 발송을 막기 위해 목록에서 뺀다
- **직원별 현재 유효 계약 하나만 보고 판정한다.** 과거 만료 계약은 조회 대상이 아니므로 한 직원이 여러 행으로 뜨지 않는다
- **회수된 건은 제외 대상이 아니다.** 계약서가 없는 상태이므로 다음 조회에 다시 잡힌다 — 이것이 재발송 경로다 (§6)

### 4.3 계약 종료일 자동 계산

기준일과 근속기간은 **시스템 설정값**으로 뺀다. 정책이 바뀌면 개발 없이 설정만 변경한다.

| 설정 | 기본값 |
|---|---|
| 연봉 인상 기준일 | 2월 28일 |
| 인상 대상 최소 근속기간 | 12개월 |

```
종료일 기본값 = (입사일 + 최소 근속기간) 이상인 첫 인상 기준일
```

| 입사일 | 종료일 기본값 |
|---|---|
| 2025-08-01 | 2027-02-28 |
| 2026-02-28 | 2027-02-28 |
| 2026-03-01 | 2028-02-28 |

자동 산출값은 기본값일 뿐이며 담당자가 수정할 수 있다 (정책서 `:295`).

### 4.4 STEP 3 — 편집 그리드

N명 × M필드를 한 화면에서 보고 수정하는 스프레드시트형 그리드. **현재 값과 변경 후 값을 나란히 놓아** 형평성을 눈으로 비교할 수 있게 한다.

#### 근로계약서

| 사번 | 이름 | 근로유형 | 계약서 종류 | 계약기간 시작일 | 계약기간 종료일 | |
|---|---|---|---|---|---|---|
| | | *읽기 전용* | **기간제 / 정규직** | | | 미리보기 |

- **계약서 종류에서 `정규직` 을 선택하면 계약기간 종료일이 `기간의 정함 없음` 으로 바뀌고 입력이 잠긴다**
- 근로유형은 직원 마스터 값이라 수정 불가

#### 임금계약서 — 연봉제 (정규직 · 계약직)

| 사번 | 이름 | 현재 계약 금액 | 인상 후 계약 금액 | 현재 월 기본급 | 인상 후 월 기본급 | 현재 월 고정연장근무수당 | 인상 후 월 고정연장근무수당 | |
|---|---|---|---|---|---|---|---|---|
| | | 연봉 n원 | **연봉 n원** | | *자동* | | *자동* | 미리보기 |

**인상 후 계약 금액(연봉)만 입력하면 월 기본급·고정연장근무수당이 자동 계산된다.** 산식은 `autoCalcWageEditor()` (`:1877`) 와 동일하다.

```
M = 연봉 / 12
W = 고정OT시간 × 배율(1.5)
월기본급   = M × 209 / (209 + W)
고정연장수당 = M × W  / (209 + W)
```

> ⚠️ 계산 기준값은 **연봉**이다. 월 기본급에 인상률을 걸면 안 된다. `autoCalcWageEditor()` 는 DOM 에 직접 물려 있어 N행 그리드에 못 쓰므로 **순수 함수 `calcWage()` 로 분리**해 편집기·그리드가 공유한다.

#### 임금계약서 — 시급제 (일용직)

| 사번 | 이름 | 현재 계약 금액 | 인상 후 계약 금액 | 현재 주휴수당 | 인상 후 주휴수당 | 1일 소정 근로시간 | 1주 소정근로일 | |
|---|---|---|---|---|---|---|---|---|
| | | 시급 n원 | **시급 n원** | | *자동* | | | 미리보기 |

주휴수당은 시급의 20% 로 자동 산출한다.

#### 임금계약서 — 계약기간·총 계약금액 (프리랜서)

| 사번 | 이름 | 현재 계약 금액 | 인상 후 계약 금액 | 현재 월 지급액 | 인상 후 월 지급액 | |
|---|---|---|---|---|---|---|
| | | 총 n원 | **총 n원** | 월 n원 | *자동* | 미리보기 |

월 지급액 = `총 계약금액 ÷ 계약기간(월)`.

#### 공통

- 상단에 `전체 [ ]% 적용` 으로 인상 후 금액을 일괄로 채우고 예외만 덮어쓴다
- 인상 없이 갱신되는 대상은 발송 직전에 확인 — `인상 없이 갱신되는 대상 3명 — 확인하셨나요?`
- **임시저장 없음**

### 4.5 엑셀 라운드트립

편집 그리드 화면 안에서 다운로드·업로드한다.

```
대상자 확정 → 편집 그리드 표시 → [양식 다운로드] → 엑셀에서 값 입력
            → [업로드] → 그리드에 반영
```

양식은 **그리드에 보이는 컬럼 그대로** 내려준다. 읽기 전용 컬럼(사번·이름·현재 값)은 시스템이 채우고, 입력 컬럼만 비워서 준다.

```
[A] 사번  [B] 이름  [C] 현재 계약 금액  │  [D] 인상 후 계약 금액
  └────── 시스템 채움 (읽기 전용) ──────┘   └── 담당자 입력 ──┘
```

- **매칭 키는 사번**
- **숨김 시트에 배치 ID + 다운로드 시각**을 심고 업로드 시 대조 — 다른 배치의 파일을 올리는 사고를 막는다
- 업로드 결과 리포트

```
✅ 매칭 30명
⚠️ 값 없음 2명   — 엑셀에서 비워둠. 인상 없이 갱신하시겠습니까?
⚠️ 대상 제외 1명 — 다운로드 이후 퇴사 처리됨
```

### 4.6 STEP 4 — 발송

- **결재를 타지 않는다.** 작성 후 즉시 발송
- 발송 단위로 계약 내역에 1건 기록
- 기존 `doBulkSendForSign()` (`:1153`) 재사용

## 5. 상태 정의

### 5.1 계약서 단위

| 상태 | 의미 |
|---|---|
| 서명 대기 | 발송 후 근로자 서명 전 |
| 서명 완료 | 근로자 서명 완료 |
| **계약 완료** | **권한자 서명 완료** — 계약 성립 |
| 회수 완료 | 회수한 경우 |

- **`반려` 는 두지 않는다.** 근로자가 조건에 동의하지 않으면 협의하여 조정한 뒤 서명한다. 조건 변경이 필요하면 회수 후 재작성한다
- 권한자 서명이 마지막이므로 **근로자 서명 후에도 권한자 서명 전이면 회수할 수 있다**

### 5.2 발송 단위

| 상태 | 조건 |
|---|---|
| 계약 진행 중 | 유효 건 중 미결 > 0 |
| 계약 완료 | 유효 건 전부 계약 완료 |
| 계약 회수 | 유효 건 = 0 (전부 회수) |

**회수 건은 분모에서 제외한다.** 회수는 진행이 아니라 종결이므로, 모수에 남겨두면 발송건이 영원히 `계약 진행 중` 에 머문다.

```
유효 건 = 전체 − 회수
```

| 상황 | 유효/미결 | 상태 표시 |
|---|---|---|
| 20 완료 · 7 대기 · 5 회수 | 27 / 7 | `계약 진행 중 20/27 · 회수 5` |
| 27 완료 · 5 회수 | 27 / 0 | `계약 완료 27/27 · 회수 5` |
| 32 회수 | 0 / 0 | `계약 회수 32` |

**회수 사유와 무관하게 항상 분모에서 제외한다.** 재발송 예정이든 대상 제외든 그 발송건에서는 종결이며, 재발송은 새 발송 건으로 처리한다 (§6).

> **`계약 일부 회수` 같은 상태를 따로 두지 않는다.** 그것은 *진행 상태* 축이 아니라 *결과 구성* 축이고, 구성은 상태 셀의 숫자에 이미 나온다. 한 컬럼에 두 축을 담으면 상태가 3개에서 5개로 늘어난다.

### 5.3 계약서 이력 상태 필터 수정

현재 필터(`:861-868`)를 새 상태 정의에 맞춘다.

```diff
  { value: 'signing',  label: '서명 대기' },
+ { value: 'signed',   label: '서명 완료' },
- { value: 'active',   label: '서명 완료' },
+ { value: 'active',   label: '계약 완료' },
- { value: 'rejected', label: '반려' },
+ { value: 'canceled', label: '회수 완료' },
  { value: 'expiringSoon', label: '만료 임박' },
  { value: 'expired',      label: '만료' },
  { value: 'voided',       label: '무효' },
```

`canceled` 가 없어 **회수한 건이 조회에서 사라진다.**

## 6. 회수

| 대상 | 가능 여부 |
|---|---|
| 서명 대기 · 서명 완료 | ✅ 회수 가능 (권한자 서명 전) |
| 계약 완료 | ❌ 불가 — 정정이 필요하면 새 계약 작성 |
| Route 1 최초 계약 | ❌ 불가 |

- 발송건 전체 회수 · 개별 선택 회수 모두 지원
- **사유 입력 필수** — 계약서는 삭제 없이 누적 보존되므로(`:484-486`) 사유가 없으면 감사 시 근거가 없다
- **근로자에게 회수 통지** — 없으면 서명하러 들어왔는데 문서가 없어 문의가 발생한다

### 회수는 항상 종결이다

회수 사유가 무엇이든 **그 발송건에서는 종결 처리**한다. 원래 발송 건에 다시 붙이지 않는다.

**재발송은 새 발송 건으로 처음부터 진행한다.** 대상자를 다시 선택하는 부담은 없다 — 회수된 사람은 계약서가 없으므로 **같은 조회 조건으로 다시 뽑으면 그 사람만 나온다.**

```
2027-02 연봉 인상 발송 (32명)
  → 27명 계약 완료 · 5명 회수                    [계약 완료]

같은 조건으로 재조회
  → 27명은 새 계약 종료일이 2028-02-28 이라 안 걸림
  → 5명만 기존 계약(종료일 2027-02-28)이 남아 있어 그대로 잡힘
  → 조건 수정 후 새 발송 건으로 발송
```

발송 건이 둘로 나뉘지만, 각 건이 명확히 종결되어 목록에서 미결이 남지 않는다.

> 급여 공백은 발생하지 않는다 — 정책서 `:291` "임금계약 만료 후 새로운 임금계약이 체결되지 않은 기간에는 직전 임금계약 조건을 계속 적용". 다만 **인상 전 금액으로 지급된다**는 점은 회수 시 안내한다.

